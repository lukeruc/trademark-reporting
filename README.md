# 商标字号统计

线上填写原 Excel 第 2—6 张表；导出完整六张表，第 1 张保留原空白模板。业务角色只有**管理员**和**企业用户**。

## 启动

仓库只包含源码、依赖清单和静态资源，不包含 conda 环境、账号、填报数据或应用密钥。首次安装需创建环境，之后手动激活；脚本不会创建、激活或切换环境。

~~~bash
git clone https://github.com/lukeruc/trademark-reporting.git
cd trademark-reporting
conda env create -f environment.yml
conda activate trademark-reporting

# 首次设置管理员账号和密码，完成后退出
./setup_admin.sh

# 启动网页服务
./start.sh
~~~

启动脚本会识别本机 IP、准备本应用的数据库及数据表、收集静态文件，并显示可以访问的网址。无需手工创建数据库、数据库账号或设置连接密码，也无需配置 systemd 或 Nginx。

网页服务使用 Gunicorn 的 `gthread` 模式，运行 3 个工作进程、每个进程 4 个线程。已连接但未发送 HTTP 数据的空连接会单独超时关闭，避免占住同步工作进程后触发 `WORKER TIMEOUT`。这些参数由启动脚本管理，无需填写额外配置。

管理员设置脚本支持显示已有管理员、新建管理员、重设管理员密码；输入密码时终端不显示字符。它不会将企业用户升级为管理员。

## .env 只保留端口

默认不需要 .env，也无需填写任何配置。只有需要更换网页端口时，才复制 .env.example 为 .env 并修改这一项：

~~~text
APP_PORT=7070
~~~

7070 未被占用就无需修改。它是网页访问端口。IP、数据库连接、应用密钥、文件目录等全部由程序处理。

启动后，使用终端显示的实际内网网址，例如：

~~~text
http://192.168.1.20:7070/
~~~

首次启动时会自动生成登录二维码并保存。管理员在“入口二维码”页面直接截图即可，无须填写地址或点击生成。页面只展示已保存的图片；普通重启复用，IP 或端口变化时在启动阶段更新。

设备需能够访问公司内网，扫码后进入登录页。地址自动优先选用默认路由所在网卡，二维码不随管理员使用 localhost 或其他访问地址而改变。

## 环境依赖

环境清单包含 Python 3.12、PostgreSQL 16 及应用依赖。若已有环境但缺少依赖，手动激活后执行：

~~~bash
conda install -c conda-forge postgresql=16
python -m pip install -r requirements.txt
~~~

用普通 Linux 用户运行脚本，不使用 sudo 启动。软件安装和环境激活均由你手动执行。

## 在 tmux 中持续运行

~~~bash
tmux new -s trademark
cd /你的路径/trademark-reporting
conda activate trademark-reporting
./start.sh
~~~

按 Ctrl+B，松开后按 D，分离会话后网页服务继续运行。重新进入：

~~~bash
tmux attach -t trademark
~~~

Ctrl+C 停止网页服务；再次运行 start.sh 即可启动。底层数据库由程序自动启动并在本机复用，不需要单独操作。主机重启后重新手动激活 conda，再运行 start.sh；程序自动恢复数据库及网页服务。

## 管理员与企业用户

管理员负责创建和删除企业账号、查看报送进度及已提交信息、退回、汇总导出和二维码管理。各企业用户只能填写自身负责范围的数据并报送。

- 管理员在报送管理列表点击“企业信息”，可分别重置用户名和密码。用户名仍按企业全称拼音首字母生成；新密码为随机 8 位字母数字组合，仅在重置结果页显示，请及时保存并交付填报人。
- 重置密码后旧密码及旧登录会话失效，企业已填写、已提交的数据不变。企业用户不能调用账号重置功能。
- 删除账号须从“企业信息”页进入专门的删除确认页，核对企业、用户名和各类数据数量，手动输入完整企业名称及用户名，并勾选永久删除确认后提交。管理员账号不能通过此功能删除，企业用户无权调用。
- 删除账号会同时删除该账号下本企业及下属企业的全部信息、填报明细、历史报送和图样，从汇总中移除，旧登录会话失效，无法恢复。确认期间如企业数据、报送状态或账号凭据发生变化，原删除确认会被拒绝，须重新进入页面核对。
- 企业账号为全称的拼音首字母，如“中设工业科技公司”生成 zsgykjgs；重名追加数字。
- 企业初始密码为随机 8 位字母数字组合，且两类字符都包含。
- 公司本部使用单独的填报账号。三级企业统一录入本企业及其下属企业，添加企业记录不生成账号。
- 企业全称、实际产权级次和性质统一在“企业信息”页维护。境内、境外注册商标的持有人名称及级次直接引用对应实际企业，不在商标明细中重复填写；草稿随企业资料更新，已提交历史版本保留当时信息。
- 原表要求“是/否”的下拉框只提供“是”和“否”；“有/无”字段继续沿用原表选项。
- 填写后先保存草稿，再统一提交。提交后整批锁定；企业可申请退回，只有管理员退回后才能修改。
- 当前已提交版本进入汇总；退回期间暂时排除，重报后用新版本替换。
- 五类内容均可直接确认“无”，包括企业字号及境内外未注册商标，无需新增明细；提交和导出均保留确认结果。企业字号导出“是否有字号”为“否”，商标无记录时件数为 0。
- 企业性质按原表保留：第 6 张表 C3、C4 要求填写“层级及性质（产权层级，全资、控股、实际控制）”。
- Excel 使用原模板副本，保留六张表、分区、说明和图片，必要时自动扩行。

数据库底层连接身份由程序使用，不是第三种网页登录角色。不收集证明材料，不提供子账号、盖章 PDF 或 OA 登录集成。

## 数据保存

数据位于应用目录内：

| 位置 | 内容 |
| --- | --- |
| var/database | PostgreSQL 数据 |
| var/secret.key | 自动生成并复用的应用密钥 |
| var/marks | 已上传的商标图样 |
| var/entry-qr | 启动时生成的登录二维码图片 |
| resources/统计表模板.xlsx | 原始 Excel 模板 |
| .env | 网页端口 |

程序不会在重启时重新创建或清空已有数据库。应用密钥和图样应与数据库一起保留。

运行中的数据库不能直接复制其数据目录作为有效备份。需要备份或迁移时，应先使用 PostgreSQL 的备份工具，或完整停止数据库后再复制；不要删除 var 目录。

## 常见启动提示

- 环境不符合要求：手动激活 Python 3.12 项目 conda 环境。
- 缺少 PostgreSQL：在激活的环境中手动安装 postgresql=16。
- 缺少 Python 依赖：在激活的环境运行 python -m pip install -r requirements.txt。
- 尚未设置管理员：先运行 setup_admin.sh。
- 端口被占用：修改 APP_PORT，或停止此前启动的网页服务。
- 数据库初始化失败：查看 var/database.log，确认项目目录可写；程序不会删除已有数据。
- 其他设备打不开：使用服务器实际内网 IP，确认网络连通及端口可达。
